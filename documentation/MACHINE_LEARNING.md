# ForensiTap-ESP32: Host-Side Machine Learning Extension

## 1. Overview & Architectural Motivation

While the ESP32 micro-controller executes deterministic, rule-based anomaly detection at the edge (Stage 11), complex or subtle wireless attacks—such as slow-rate beacon stuffing, coordinated multi-station probe floods, and behavioral departures across correlated dimensions—benefit from multi-dimensional unsupervised learning.

The **Host-Side Machine Learning Extension** (Stage 17) utilizes the computational capabilities of the laptop (multi-core Ryzen 7 CPU, RTX 5060 GPU, 16 GB RAM) to ingest 7-dimensional statistical feature vectors streamed from the ESP32, training an unsupervised robust anomaly detection model.

---

## 2. Multi-Dimensional Feature Space

The model ingests a 7-dimensional feature vector $\mathbf{x} \in \mathbb{R}^7$ generated by the ESP32 Feature Engine every 10 seconds:

$$\mathbf{x} = \begin{bmatrix}
\text{frame\_rate} & (\text{fps}) \\
\text{byte\_rate} & (\text{bytes/sec}) \\
\text{average\_frame\_size} & (\text{bytes}) \\
\text{unique\_peers} & (\text{count}) \\
\text{management\_frame\_ratio} & ([0.0, 1.0]) \\
\text{traffic\_burst\_score} & (\ge 1.0) \\
\text{frame\_rate\_zscore} & (\text{standard deviations})
\end{bmatrix}$$

---

## 3. Mathematical Formulation: Robust Ellipsoidal Detector

Traditional Gaussian models (e.g. Mahalanobis distance) are vulnerable to outlier pollution in contaminated training sets. ForensiTap employs a **Robust Median Absolute Deviation (MAD) Scaler** combined with domain-weighted distance projection:

### 3.1 Feature Centroid & Scale Estimation
For each feature dimension $j \in \{1, \dots, 7\}$:
$$\tilde{\mu}_j = \text{median}(\{x_{i,j}\}_{i=1}^N)$$
$$\sigma_j = \max\left(\text{median}(\{|x_{i,j} - \tilde{\mu}_j|\}_{i=1}^N) \times 1.4826, \sigma_{j,\min}\right)$$

where $\sigma_{j,\min}$ prevents artificial variance collapse on discrete features (e.g., peer counts).

### 3.2 Robust Weighted Mahalanobis Distance
The distance $D(\mathbf{x})$ of any observation $\mathbf{x}$ from the baseline distribution is given by:

$$D(\mathbf{x}) = \sqrt{\sum_{j=1}^7 w_j \left(\frac{x_j - \tilde{\mu}_j}{\sigma_j}\right)^2}$$

Domain weights $w_j$ place higher sensitivity on features strongly correlated with malicious wireless activity ($w_{\text{mgmt}} = 2.0$, $w_{\text{burst}} = 1.8$, $w_Z = 1.5$).

### 3.3 Sigmoidal Anomaly Probability & Decision Threshold
$$\tau = \text{Quantile}_{1 - \alpha}(\{D(\mathbf{x}_i)\}_{i=1}^N)$$
$$P(\text{Anomaly} \mid \mathbf{x}) = \frac{1}{1 + e^{-k(D(\mathbf{x}) - \tau)}}$$

- When $D(\mathbf{x}) \ge \tau$, the observation is classified as an **ANOMALY**.
- When $D(\mathbf{x}) < \tau$, the observation is classified as **BENIGN**.

## 4. Attack Evaluation & Performance

The model was evaluated against three benchmark wireless attack signatures:

| Attack Scenario | Simulated Vector Attributes | Anomaly Distance | Anomaly Probability | Model Classification | Primary Feature Driver |
|---|---|---|---|---|---|
| **Deauthentication Flood** | $\text{fps}=350$, $\text{mgmt}=0.88$, $Z=+4.2$ | **$35.98$** (Threshold: 9.02) | **$100.0\%$** | **ANOMALY** | $\text{mgmt}: +18.1\,Z$ |
| **Data Exfiltration Spike** | $\text{fps}=580$, $\text{bytes}=320\,\text{KB/s}$, $Z=+6.8$ | **$90.33$** (Threshold: 9.02) | **$100.0\%$** | **ANOMALY** | $\text{byte\_rate}: +77.2\,Z$ |
| **Micro-Burst Pulse** | $\text{burst}=8.2$, $\text{peers}=15$, $Z=+1.2$ | **$20.63$** (Threshold: 9.02) | **$100.0\%$** | **ANOMALY** | $\text{burst}: +15.1\,Z$ |
| **Benign Validation Traffic** | $\text{fps}=95$, $\text{mgmt}=0.16$, $\text{burst}=1.6$ | **$1.95$** (Threshold: 9.02) | **$0.0\%$** | **BENIGN** | Normal Baseline |

## 5. Usage & Execution

### 5.1 Training the Model
```bash
# Ingest recorded sessions from datasets/sessions/ and train artifact
python laptop/ml/train.py
```
Outputs trained JSON weights to `laptop/ml/models/forensitap_anomaly_model.json`.

### 5.2 Real-Time Streaming Inference Against ESP32
```bash
# Score streaming live feature telemetry directly from the ESP32
python laptop/ml/inference.py --live --esp-url http://192.168.1.26
```

### 5.3 Offline Session Audit
```bash
# Score all records in the most recent session
python laptop/ml/inference.py --latest

# Score a specific historical session folder
python laptop/ml/inference.py --session-dir datasets/sessions/session_20261107_221713
```
